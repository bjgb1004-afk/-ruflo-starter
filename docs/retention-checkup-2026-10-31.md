# 삭제율 점검 결과 (2026-10-31)

광고를 켜기 전에 삭제율부터 내리려고 한 점검이다. 수치는 Play Console과 Firebase 화면에서 직접 읽은 값이다(기간: 10월 3일~10월 30일, 28일).

| 설치 수 / 평균 평점 | 159 / 평점 없음(리뷰 1건) | Play Console |

## 해석
- 삭제율 약 19%는 Firebase 기준으로 확인됐다.
- Play Console의 Android vitals는 **데이터가 없다**(사용자가 적어 집계되지 않음). 그래서 "강제 종료가 원인인지"는 Play Console로는 알 수 없고, Sentry 쪽을 봐야 한다.
- 삭제 직전에 어떤 화면을 봤는지는 **표준 보고서에서 볼 수 없다.** GA4 탐색(Exploration)의 경로 분석이 필요하다. 아직 만들지 않았다.
- Play Console의 개선 권장: 비트맵 이미지 최적화, R8 최적화(메모리 사용량, 출시 1.0.0 기준).

## 코드/문서로 처리한 것
- 5번: 설정에 "불편한 점·의견 보내기"를 넣었다가 **2026-11-01에 앱에서 다시 뺐다**(의견 0건 상태에서). 창구 자체는 동작했지만 들어온 의견을 알려줄 방법이 없었다 - Supabase 대시보드에 직접 들어가야만 보였다. 알림을 붙이는 세 가지(메일 발송 서비스 연동, GitHub Actions로 개수만 알림, 관리자 화면 표시)를 모두 번거롭다고 보고 기능을 접었다.
  - 표 `public.app_feedback`과 마이그레이션 `20261031000000`은 **그대로 남겨뒀다.** 빈 표라 비용이 없고(500MB 한도에서 한 건이 0.4KB), 되살릴 때 마이그레이션을 다시 쓰지 않아도 된다. 되살리려면 앱 쪽 폼만 다시 만들면 된다.
  - 되살릴 때 같이 정할 것: 들어온 걸 어떻게 알 것인가. 그게 없으면 또 같은 이유로 접게 된다.
  - 메일(mailto)로 대신하는 건 검토해서 접었다. 유저 이메일 주소가 항상 노출되어 Play 데이터 보안 선언을 고쳐야 하고(아래 불일치 항목 참고), 메일 앱이 없는 폰에서는 아무것도 열리지 않아 화난 유저가 결국 스토어 리뷰로 간다 - 이 기능을 만든 이유와 반대 결과다.
- 4번: `docs/play-store-listing.md`에 빠졌던 기능(천재들의 한수, 놓친 당첨금, 스피또 현황)을 추가하고 불일치 3건을 메모했다.

## 첫 실행 경험(3번)에서 찾은 문제 - 아직 고치지 않음
- `useCurrentLocation`이 홈 화면이 뜨자마자 OS 위치 권한 창을 띄운다. 그런데 "위치 권한이 필요합니다" 설명 모달(`app/(tabs)/index.tsx`)은 로딩이 끝난 뒤 맨 아래 return에서만 그려진다. **OS 창이 설명보다 먼저 뜬다.** 거부한 사람에게는 "권한이 필요합니다"가 뒤늦게 나온다.
- `app/_layout.tsx`는 앱을 열 때 OTA가 있으면 받자마자 `reloadAsync()`로 앱을 다시 시작한다. 처음 설치한 사람도 열자마자 앱이 한 번 꺼졌다 켜질 수 있다. 의도된 동작이지만 첫 실행에서는 거슬릴 수 있다.
- 위 두 파일은 2026-10-31 21:37에 다른 세션이 막 수정한 파일이라 충돌을 피하려고 건드리지 않았다.
