[전국 로또 지도 통계 플랫폼 앱 - 데이터 수집 및 백엔드 고도화 설계서]

1. 프로젝트 개요
- 서비스명: 전국 로또 지도 통계 플랫폼 (Android / iOS)
- 목적: 전국 로또 판매점 위치, 1/2등 당첨 이력, GPS 기반 반경 검색, 스마트 추천 점수(store_score) 및 명당 랭킹 제공
- 운영 제약: 초기 비용 0원 (Supabase Free Tier, GitHub Actions, 네이버 지도 SDK 활용)

2. 확정 기술 스택
- 앱 프레임워크: React Native + Expo (Expo Router, TypeScript)
- 지도: 네이버 지도 SDK (@react-native-seoul/naver-map)
- 백엔드/DB: Supabase (PostgreSQL + PostGIS)
- 상태 관리: TanStack Query + Zustand
- 위치/GPS: expo-location
- 모니터링/보안: Sentry + PostHog + Cloudflare
- 데이터 배치: GitHub Actions (매주/매일 자동 실행)

3. 데이터 수집 및 식별 알고리즘 상세 설계

1) 위치 기반 고유 식별자 (`store_id`)
- 상호명/주소 변경에 견디는 UUID v5 생성 전략 적용
- 생성 키: SHA-1( Namespace + 행정동코드 + 도로명/지번 본번·부번 + 소수점 4자리 좌표 )
- 브랜드/상호가 바뀌어도 물리적 입지가 유지되면 동일 store_id를 유지함.

2) 주소 정규화 모듈 (Address Normalizer)
- 동행복권 텍스트와 공공데이터포털 주소 표기 격차 해소
- 광역시도 통일('서울' -> '서울특별시'), 불용어/층수/호수 제거, 특수문자 정규화 후 Geocoding 입력.

3) 단계적 반경/유사도 매칭 (Cascading Match)
- 1단계 (20m 이내): 상호 유사도 60% 이상 시 즉시 매칭
- 2단계 (50m 이내): 상호 유사도 80% 이상 시 매칭
- 3단계 (100m 이내): 건물 본번/부번 완벽 일치 시 매칭

4) 데이터베이스 스키마 및 물리 집계 테이블 (`store_ranking_stats`)
- 성능을 위해 일반 View 대신 물리 테이블(Physical Table)로 운영하며 배치가 UPSERT 갱신.
- 주요 컬럼:
  * id (UUID v5), name, address, location (GEOGRAPHY Point)
  * first_prize_count, second_prize_count (누적 1/2등)
  * first_prize_1yr, first_prize_5yr (최근 1년 / 5년 1등)
  * last_first_prize_draw, last_second_prize_draw
  * nation_rank, province_rank, city_rank
  * store_score (추천 점수)
  * updated_at

5) 스마트 추천 점수 알고리즘 (`store_score`)
- 공식: (최근 1년 1등 수 * 50) + (최근 1년 2등 수 * 10) + (누적 1등 수 * 5) - (현재 거리km * 15)
- 내비게이션 및 이동 경로 추천 모드에서 유저에게 최적의 명당을 우선 노출함.

4. 개발 요청 사항
1) `scripts/ingest/` 내 데이터 수집 및 매칭 파이프라인 스크립트(Address Normalizer, Cascading Matcher, UUID v5 generator 포함)를 구현해줘.
2) 위 요구사항이 반영된 Supabase 초기 마이그레이션 SQL(`supabase/migrations/`)을 생성해줘.
3) 해당 내용을 정리한 최신 README.md를 프로젝트 루트에 생성/갱신해줘.
